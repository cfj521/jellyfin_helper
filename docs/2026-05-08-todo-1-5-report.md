## 第 2 条 — 剧集勾选完整加载

### 问题根因
[LibraryDetail.vue:775](web/frontend/src/views/jellyfin/LibraryDetail.vue:775) `toggleRowSelection` 走 `_walkRowAndDescendants` 时仅查 `childrenMap`。**用户不展开就勾 Series → childrenMap 里没该 series 的 children → 只把 Series 自己加进 selectedItems**，下游批量操作只对 series 这一层生效，跳过了所有 Season / Episode。

原代码有「续选」机制（loadChildren 完成时检查父级选中状态），但只覆盖"展开后再勾父级"路径，**反向"勾父级后再展开"路径未覆盖**。

### 修复 [LibraryDetail.vue:775-840](web/frontend/src/views/jellyfin/LibraryDetail.vue:775)
- `toggleRowSelection(row, true)` 时，UI 立即把 row 自己加进 selectedItems（瞬时反馈）
- 检测到 `row.has_children && !childrenMap[row.id]` → fire-and-forget 触发 `_cascadeLoadAndSelect(row)`
- `_cascadeLoadAndSelect` 递归：拉本层 children → 写 childrenMap → 父级仍选中则把 children 加进 selectedItems → 对每个 child 再递归（Series → Season → Episode 三层）
- 已展开一级但未展开二级时也会走递归（覆盖"展开了 Season 列表但没展开任何 Season"的情况）

**决策**：fire-and-forget 不 await，避免 checkbox 点击 UI 卡顿几秒；用户看到的是 row 立即被勾上，~1-2s 后 batch 操作的目标数会"自己变多"。这比"勾选后转圈"体验更好。

**测试方法**：剧集库详情页，**不展开**树，直接点 Series 行 checkbox → 立即看到主选项打勾；底部"已选 N 项"或工具栏 scope 应在 ~1-2s 内涨到该 Series 的总集数。

## 第 3 条 — 重复检测逻辑修正

### 问题根因
[media.py:240](web/backend/api/media.py:240) 现行 `find_duplicates` 仅按 byte 粒度（文件大小 + 首尾 64KB hash）。**这能识别"完全相同的两个文件"，但识别不出真正的语义重复**——比如「同一部电影的 1080p 和 4K 两份」、「同一集动漫的不同字幕组版本」。这些 byte 不同但内容是同一作品，对用户而言才是该清理的"重复"。

### 改进策略：新增「Jellyfin 元数据」检测模式（推荐默认）

**后端** [media.py:348](web/backend/api/media.py:348) `GET /api/media/duplicates-by-metadata?library_id=xxx`
- 拉库下所有 Movie + Episode（带 ProviderIds / Path / MediaSources / SeriesId / Season+Episode）
- 分组规则按优先级：
  - **Movie**：ProviderIds.Tmdb（最强）→ ProviderIds.Imdb → normalize(Name) + ProductionYear（兜底）
  - **Episode**：SeriesId + ParentIndexNumber + IndexNumber
- `used_ids` 防止 movie 被多 key 重复归组
- 组按"可释放空间"排序（除最大文件外的总大小），用户看到的第一组就是清理收益最高的
- 不扫盘，几千 item 的库瞬时返回

**前端** [LibraryDetail.vue:460](web/frontend/src/views/jellyfin/LibraryDetail.vue:460) 重复检测对话框
- 新增「检测模式」radio：`metadata`（默认推荐）/ `hash`
- metadata 模式 UI 多展示：组级 match_type 标签（TMDB 同 ID / IMDB 同 ID / 标题+年份 / 同剧·同季·同集）+ 标题 + 年份
- 切换 mode 自动清空旧结果避免渲染错位
- 旧 hash 模式 UI 完全保留，用户仍能用

**决策**
- 没动旧 `/duplicates` 端点，向后兼容
- 没合并两个端点的响应结构（语义不同：metadata 看 Jellyfin Item ID，hash 看文件 path），让前端按 mode 分开渲染

**测试方法**：进任意大库的详情页 → 重复检测 → 默认 metadata 模式 → 应该看到 TMDB 同 ID / 同剧同集组（如果库里真有重复）。切到 hash 模式应该能跑老逻辑。

## 第 4 条 — Shooter / Kitsunekko + Bazarr 风格评分

### 决策
原架构：每个 provider 自己 sort 候选返回 best。这导致跨源比较时无统一标准。

我搭了一个**共用评分模块**（scoring.py）+ **两个新 provider**（shooter.py / kitsunekko.py），新源用 scoring 选 best；老源 OpenSubtitles / assrt 沿用各自排序逻辑，没动以避免回归（评分集成它们是 nice-to-have，留待后续）。

### 1) `tools/subtitle_downloader/scoring.py`（新增）
Bazarr 风格评分（参考其 wiki 文档常量值）：
| 维度 | 分值 | 说明 |
| --- | --- | --- |
| hash 匹配 | +100 | 文件 hash 一致（最强信号） |
| TMDB ID | +60 | ProviderIds.Tmdb 一致 |
| IMDB ID | +60 | ProviderIds.Imdb 一致 |
| release group | +50 | 文件名末尾 -GROUPNAME 一致 |
| resolution | +30 | 1080p/720p/4K 等一致 |
| source | +25 | bluray/web-dl/hdtv 等一致 |
| year | +20 | 年份一致 |
| episode | +15 | S+E 编号一致 |
| language | +10 (-2/级) | 命中 preferred_langs；越靠前越优 |
| vote | 0~10 | 用户票数/下载量 normalize |

提供：
- `VideoInfo.from_filename(filename)` 从视频文件名解析 release tag / 年份 / S+E
- `SubtitleCandidate` dataclass：source / language / release_name / hash_match / vote / ... 各 provider 包装成它
- `score_candidate(cand, video, preferred_langs)` 单条打分，写入 `cand.score` + `cand.score_breakdown`
- `pick_best(candidates, video, preferred_langs)` 全部打分后返回最高分

Smoke test 通过：1080p WEB-DL RARBG 视频对应的 c1 候选拿到 143 分（release_group 50 + resolution 30 + source 25 + year 20 + lang 10 + vote 8），战胜 hash 匹配 + 弱 vote 的 c3（115 分）。

### 2) `tools/subtitle_downloader/shooter.py`（新增）
- Shooter 协议 hash：4 个 4KB 块（offset 4096 / size/3 / size*2/3 / size-8192），每块 md5 + ";" 拼接
- POST `https://www.shooter.cn/api/subapi.php`，form 字段 filehash / pathinfo / format=json / lang=Chn|Eng
- 返回 `[{Desc, Files: [{Ext, Link}]}]`；空结果是 b'\xff' 单字节
- `guess_lang_from_desc()` 启发式从 Desc + 文件链接判定语言（含"简体 / 繁体 / English / 日本"等关键词）
- `request_delay`（默认 2s）+ `_wait_quota()` 防 ban
- 无 API Key、无注册需求

### 3) `tools/subtitle_downloader/kitsunekko.py`（新增）
- 顶级日语字幕目录：`https://kitsunekko.net/dirlist.php?dir=subtitles%2Fjapanese%2F`
- BeautifulSoup 解析 HTML `<table><tr>` 列表（lxml 加速；fallback html.parser）
- `_DirectoryCache` TTL 1h 内存缓存（顶级 5000+ 项很重）
- `extract_anime_name(filename)`：剥 [字幕组] / 括号 / release tag / 集编号 / 扩展名 → 番剧名
- `fuzzy_match_directory()`：归一化（lowercase + 仅保留字母数字 + CJK + 假名 + 谚文）后双向 substring + bigram Jaccard
- `pick_best_subtitle()`：episode 编号一致 +50 / 仅集号 +30 / 字幕扩展名优先 +10 / 文件名相似 +0~20

**已知限制**：Kitsunekko 大量字幕打包成 .zip/.rar，当前实现仅下载非压缩字幕（.ass/.srt/.ssa/.vtt 等）；遇到压缩包跳过该候选继续尝试下一个候选目录。压缩包解压逻辑可参照 `assrt.py` 的 `extract_subtitles_from_archive()` 后续接入。default `enabled: false`（仅日语，多数用户用不上）。

### 4) `tools/subtitle_downloader/main.py`（改造）
- 注册新 provider：`_ShooterProvider`（含 scoring 接入）+ `_KitsunekkoProvider`
- `_PROVIDER_FACTORIES` 字典加 'shooter' / 'kitsunekko'
- 沿用回退链机制：sources 顺序尝试，第一个 success/exists 即返回

### 5) `config.yaml.example`（更新）
- 新增 `shooter_request_delay: 2.0` / `kitsunekko_request_delay: 1.5`
- `subtitle.sources` 默认顺序：shooter → assrt → opensubtitles → kitsunekko(disabled)
- 用户需把自己的 config.yaml 同步加上 shooter / kitsunekko 条目（不加默认不启用）

**测试方法**
- shooter：拿一个中文电影视频，preferred_langs 含 chs，跑字幕下载工具/UI，应该看到 source=shooter 的成功结果，dry_run 模式响应里带 `score / score_breakdown`
- kitsunekko：单独打开 enabled，跑一个日语动漫视频，preferred_langs 含 jpn
